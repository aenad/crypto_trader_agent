# حافظهٔ پایدار عامل

حافظه در SQLite و به‌طور پیش‌فرض در `data/agent_memory.sqlite3` ذخیره می‌شود. مسیر با `MEMORY_DB_PATH` در `.env` قابل تغییر است. داده‌ها بعد از ری‌استارت باقی می‌مانند؛ پوشهٔ data در gitignore است. برای انتقال یا پشتیبان‌گیری، سرویس را متوقف و کل پوشهٔ data را کپی کنید.

## موارد فعلی

- هر تحلیل موفق: خروجی buy/sell/hold، دلایل، اندیکاتورها، زمان تصمیم، نسخهٔ baseline و interval.
- راه‌اندازی سرویس: حالت اجرا و تنظیمات ریسک همان اجرا؛ هیچ توکن یا secret ذخیره نمی‌شود.
- درخواست سفارش ردشده در حالت امن: intent و پاسخ؛ این رکورد معامله یا fill واقعی نیست.
- یادداشت‌های صریح کاربر/عامل: key و متن value با زمان آخرین تغییر. این یادداشت‌ها قوانین اجرایی ریسک را تغییر نمی‌دهند.

## API

- `GET /api/memory/events?kind=decision&limit=50` تاریخچه از جدید به قدیم. فیلتر symbol اختیاری است.
- `POST /api/memory/notes` با بدنهٔ `{"key":"team.goal","value":"ثبت دلیل برای تمام تصمیم‌ها"}` یک یادداشت را ثبت یا به‌روز می‌کند.
- `GET /api/memory/context` یادداشت‌ها و ۱۰ تصمیم اخیر را برای اتصال آینده به LLM برمی‌گرداند.

API فعلی محلی و بدون احراز هویت است؛ آن را با دسترسی عمومی منتشر نکنید. اطلاعات حساب و کلیدهای اتصال در notes قرار نگیرند.

## محدودیت‌های فعلی

مدل LLM هنوز متصل نیست و هیچ promptی به‌صورت خودکار context را مصرف نمی‌کند. ذخیرهٔ تاریخچه باعث آموزش مدل یا تغییر خودکار استراتژی نمی‌شود.

این مرحله مدیریت موقعیت، جلوگیری از سفارش تکراری، تطبیق موجودی یا اجرای معامله را اضافه نمی‌کند. checkpoint کندل و وضعیت سفارش‌ها باید همراه با آداپتور اجرای واقعی و شناسهٔ سفارش صرافی پیاده شوند. تصمیم ذخیره‌شده هم مجوز اجرای دوباره نیست.

فقط خروجی تحلیل و اندیکاتورها ثبت می‌شوند؛ snapshot کامل کندل‌ها و بازپخش دقیق تحلیل هنوز پیاده‌سازی نشده‌اند. خطای نوشتن حافظه باید مانع تلقی تصمیم به‌عنوان تصمیم ثبت‌شده شود. برای تاریخچهٔ طولانی، سیاست آرشیو و ظرفیت دیسک لازم است.

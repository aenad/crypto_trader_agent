# Trading blocker investigation

Investigation date: 2026-10-23. Scope: existing Momentum Breakout, shared risk,
SHADOW and simulated execution. No new strategy, dependency, threshold change,
exchange mutation or LIVE activation was introduced.

## Answer: why trading stops

There are several separate causes, not one broken exchange connection:

1. **The existing local session is stopped.** Its health reports `running=false`,
   `status=STOPPED`, stale data, and last frame `2026-10-23T17:41:34.310448Z`.
   This describes `data/shadow-continuous/session.sqlite` in this workspace;
   it does not establish whether an Ubuntu deployment is running. The recorded
   evidence does not establish why that process stopped.
2. **While that session was receiving data, the strategy produced only HOLD.**
   All 10 evaluations failed the configured entry conditions. There were no BUY
   orders waiting for dispatch, and AI was deliberately disabled in QUANT_ONLY.
3. **On the available historical baseline, the strategy produced 8 BUY candidates,
   but all 8 failed the cost-aware risk check `FEES_ERASE_REWARD`.** The risk engine
   rejected them before quantity sizing, minimum order checks and the hard cap.
   This code covers both non-positive net reward and insufficient net reward/risk;
   it does not mean every candidate's target was below fees alone.
4. **Hybrid AI is not deployment-ready.** The baseline dataset contains zero
   eligible signals because the same eight candidates fail risk. No baseline
   frozen model can be trained/validated from it. This prevents hybrid startup,
   but is not the cause of zero trades in QUANT_ONLY.
5. **Real execution remains independently disabled.** Local LIVE candidates are
   disabled, and credit-account permission/key scope/routing review remains
   incomplete. A successful manual order is not proof of unattended readiness.

No defect that incorrectly rejects these real-data entries was demonstrated.
The confirmed software gap was missing durable execution/processing failure
diagnostics; that gap is fixed below. Zero trades remains a valid strategy result.

### Exact cost gate

For risk-adjusted entry price P, ATR stop S, ATR target T and
`c = taker_fee_rate + slippage_fraction`, existing code computes:

```text
loss_per_unit = P - S + P*c + S*c
net_reward = T - P - P*c - T*c
reject if net_reward <= 0
       or net_reward / loss_per_unit < min_net_reward_risk
```

The baseline assumes 0.1% taker fees per side and 0.1% slippage. Risk uses its
conservative cost allowance in addition to the adjusted entry reference. Historical
liquidity is a documented OHLC proxy, not recorded order-book liquidity. These
assumptions require sensitivity research; none was changed to force executions.

Prior read-only account metadata in `data/readiness/account-market-constraints.json`
reports 0.3% taker / 0.25% maker fees, minimum notional 50,000 TMN and 8-decimal
quantity precision. Those observations were not re-fetched in this task and are
not certified historical fee rates. Example SHADOW metadata differs from that
observed account metadata. A deployment/evaluation must explicitly select and
version realistic costs and constraints, rather than silently reusing placeholders.

## Changes made

- Added `src/quantpilot/diagnostics.py`, a read-only JSON projection of existing
  reports and frozen SQLite journals. It verifies journal integrity and optional
  historical input/report identity, counts decisions/orders/unique fills, and
  exports coded rejection reasons plus representative stage traces.
- Fixed a confirmed observability gap: reducer/execution failures previously
  rolled back without recording their category in the durable operational journal.
  `shadow/engine.py:ShadowEngine._execute` identifies simulated operation failures;
  `shadow/service.py:ShadowSession.process` records coded `EXECUTION_ERROR` or
  `FRAME_PROCESSING_FAILED` after restoring the authoritative checkpoint.
  Raw exception messages are not exported, logging cannot mask the original
  failure, and rollback/commit resolution remains unchanged.
- Added offline round-trip, injected execution-failure/rollback/redaction, and
  diagnostic input-identity tests in `tests/test_trading_diagnostics.py`.

Existing journals contain no newly backfilled error telemetry. Zero observed
historical execution errors cannot prove that no unlogged failure happened.
Diagnostics inspect old pinned journals without claiming current-source replay.
The old session's source identity differs from today's source; replay requires
its original source. Fresh public and synthetic journals match current source.
Never rewrite source/config/model hashes or delete leases to bypass checks.
